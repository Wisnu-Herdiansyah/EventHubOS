# Threat model (Phase 0 / Phase 1 slices: tenancy, events, identity)

Scope: control-plane API, admin web app (BFF), PostgreSQL, outbox relay. Method: STRIDE per trust boundary.
Revisit when adding public delivery (Phase 2), domains (Phase 3), billing/webhooks (Phase 4).

## Assets

Tenant business data; membership/role assignments; session tokens and cookies; audit evidence;
database credentials; outbox payloads.

## Trust boundaries

1. Internet → API (untrusted clients). 2. API → PostgreSQL (runtime role). 3. Worker →
   PostgreSQL and broker. 4. Operators → migration/bootstrap roles. 5. Browser → admin web app
   (untrusted; session cookie) → API (bearer token, trusted proxy for client IP).

## Threats and mitigations

| ID  | STRIDE          | Threat                                                                            | Mitigation (implemented)                                                                                                                                                                                                                | Residual / follow-up                                                                                  |
| --- | --------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| T1  | Elevation       | Cross-tenant read/write via guessed or swapped org/event IDs (IDOR/BOLA)          | Membership-resolved context; uniform 404; object-level tenant predicate; RLS forced on all tenant tables; tests + mutation checks                                                                                                       | Extend isolation suite to cache, assets, search, queues as they are built                             |
| T2  | Elevation       | Service-layer bug omits tenant filter                                             | RLS with fail-closed missing context; runtime role `NOBYPASSRLS`, non-owner                                                                                                                                                             | Policy correctness relies on review for new tables                                                    |
| T3  | Tampering       | Moving rows between tenants                                                       | No UPDATE grant on `organization_id`; trigger guard                                                                                                                                                                                     | —                                                                                                     |
| T4  | Repudiation     | Actor denies a change; audit altered                                              | Append-only `audit_event` (triggers block even the owner); correlation IDs; Owner/Admin audit viewer with RLS isolation (ADR-0013)                                                                                                      | Off-database audit archive and integrity hashing; audit export before GA                              |
| T5  | Spoofing        | Stolen/forged session token                                                       | 256-bit random tokens, SHA-256 at rest, expiry/revocation checked in DB; strict bearer format; logout revocation                                                                                                                        | MFA, idle timeout, revoke-all                                                                         |
| T6  | Info disclosure | Secrets/PII in logs or errors                                                     | Pino redaction; generic 500 bodies; ConfigError omits values                                                                                                                                                                            | Log PII scanning in staging                                                                           |
| T7  | Tampering       | Duplicate side effects from retries/races                                         | Idempotency keys in-transaction; outbox + consumer dedupe                                                                                                                                                                               | Outbox/idempotency retention jobs (D9)                                                                |
| T8  | DoS             | Request floods, large bodies, slow queries                                        | Rate limit (per instance), 64 KiB body limit, statement timeout, pool limits                                                                                                                                                            | Distributed rate limit (D11), WAF (D1), per-tenant quotas                                             |
| T9  | Elevation       | Privilege escalation via role assignment                                          | `canAssignRole` enforced on invite, revoke, remove, and role change (current _and_ new role); demotion/removal revokes the sender's pending invitations beyond their new authority. Mutation-tested                                     | Dedicated ownership-transfer flow                                                                     |
| T10 | Tampering       | Unsafe migration weakens isolation or destroys data                               | `db:check` lint; checksums; advisory lock; lock timeout                                                                                                                                                                                 | Staging run against production-like volume (pre-prod gate 1)                                          |
| T11 | Info disclosure | Worker reads tenant data broadly                                                  | Worker role limited to outbox delivery columns and dedupe ledger                                                                                                                                                                        | Consumers that act on tenant data need scoped roles                                                   |
| T12 | Spoofing        | Malicious correlation ID header for log injection                                 | Strict charset/length; otherwise regenerated                                                                                                                                                                                            | —                                                                                                     |
| T13 | Spoofing        | Credential stuffing / password guessing                                           | Argon2id (m=19 MiB, t=2, p=1); per-account progressive lockout; 10/min per-IP limit on auth routes; uniform `invalid_credentials`                                                                                                       | Distributed rate limit (D11), breached-password screen (D14), MFA                                     |
| T14 | Info disclosure | Account enumeration via sign-up/login responses or timing                         | Identical 202 for every sign-up outcome; hash-before-lookup; dummy-hash verify for unknown accounts                                                                                                                                     | Notify owner of re-registration attempts (D4)                                                         |
| T15 | Spoofing        | Account pre-hijacking (attacker registers victim's address first)                 | Re-sign-up of an unverified address replaces the password, bumps credential version, revokes sessions and tokens; tokens bound to version; verification revokes all sessions. Mutation-tested                                           | —                                                                                                     |
| T16 | Info disclosure | Verification token leakage                                                        | Token derived in the worker at send time (never raw in outbox/DB); SHA-256 at rest; URL fragment; single-use; 24 h TTL; TLS to Resend                                                                                                   | Rotate `EMAIL_TOKEN_SECRET` on suspicion                                                              |
| T17 | Elevation       | Direct access to credential storage                                               | No table grants; per-role SECURITY DEFINER functions with fixed search_path; Argon2id-only CHECK                                                                                                                                        | —                                                                                                     |
| T18 | Info disclosure | Email provider API key or token secret exposed via logs/errors                    | Keys only from secret manager; `EmailDeliveryError` carries code/status only; Resend SDK (which logs raw errors) not used; tests assert no leakage                                                                                      | Key rotation runbook                                                                                  |
| T19 | Spoofing        | Forged verification tokens                                                        | HMAC-SHA256 with a ≥32-char secret over the event ID; DB stores hashes; tokens single-use and bound to credential version                                                                                                               | Secret compromise allows forging tokens for in-flight events only, so treat it as a rotation incident |
| T20 | Repudiation/DoS | Lost or duplicated verification emails on retry                                   | Provider idempotency key = event ID; deterministic payload; consumer dedupe ledger; mutation-tested timeout-after-accept case                                                                                                           | Bounce/complaint webhooks                                                                             |
| T21 | Spoofing        | Forwarded or leaked invitation link used by someone else                          | Acceptance requires a verified account whose email equals the invited address; tenant resolved from the token server-side; single-use; expiry; newest-link-only. Mutation-tested                                                        | —                                                                                                     |
| T22 | Elevation       | Lockout by removing or demoting every Owner                                       | All active Owner rows locked before removal or demotion; last Owner can be neither removed nor demoted (concurrency-tested)                                                                                                             | Ownership transfer flow                                                                               |
| T23 | Info disclosure | Enumerating other tenants' members via helper functions                           | `organization_members` / `organization_has_member_email` refuse any org but the current tenant context; invitation token hashes unreadable by the runtime role                                                                          | —                                                                                                     |
| T24 | Spoofing        | Session token theft via XSS or script access                                      | Token only in an `HttpOnly`, `Secure`, `SameSite=Lax` `__Host-` cookie; nonce-based CSP with `strict-dynamic`, no inline/eval; React escaping; no tenant HTML. e2e asserts flags and nonces (mutation-tested)                           | Session idle timeout, revoke-all (T5)                                                                 |
| T25 | Tampering       | CSRF against admin mutations                                                      | Server Actions only; Next.js Origin-vs-Host check; `SameSite=Lax`; `form-action 'self'`. e2e forges a cross-origin action                                                                                                               | —                                                                                                     |
| T26 | Spoofing        | Open redirect after sign-in used for phishing                                     | `safeNext` allows only same-site paths; unit and e2e tests (mutation-tested)                                                                                                                                                            | —                                                                                                     |
| T27 | Spoofing/DoS    | Client spoofs `X-Forwarded-For` through the admin app to dodge per-IP auth limits | Admin forwards only the entry appended by its N trusted proxies (`ADMIN_TRUSTED_PROXY_HOPS`); API trusts only listed proxy IPs                                                                                                          | Deployments must set both values (ADR-0014)                                                           |
| T28 | Info disclosure | Clickjacking or token leakage via Referer                                         | `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`; tokens in URL fragment, removed from the address bar                                                                                                 | —                                                                                                     |
| T29 | Spoofing        | Account takeover through the password reset flow                                  | Single-use 256-bit token (HMAC-derived per event, SHA-256 at rest), URL fragment, 60-min TTL, bound to credential version; completion revokes every session and emails the owner. Mutation-tested (version binding, session revocation) | MFA; breached-password screen                                                                         |
| T30 | Info disclosure | Account enumeration via the reset request                                         | Identical 202 response and UI message for every address; audit stores outcome, never the address                                                                                                                                        | Timing differs by one outbox insert                                                                   |
| T31 | DoS             | Flooding a victim's inbox with reset emails                                       | Per-account cap (3 per 15 min) counted under row lock, independent of client IP; per-IP limit on top. Mutation-tested                                                                                                                   | Distributed rate limit (D11)                                                                          |
